# Knowledge Base Pipeline

Everything Vaani knows offline — emergency numbers, government scheme
summaries, how-to guides — is built here and shipped as **per-language
packs** (see `docs/language-pack-spec.md`). No ML dependencies, no network
at build time, standard library only.

```
knowledge/sources/*.json          curated, cited, public-domain documents
        │
        ▼  build_kb.py            validate → build/kb.json (always)
        │                                  → build/kb.sqlite (FTS5, when available)
        ▼  build_embeddings.py    nv-hash-v1 vectors → build/embeddings.{json,bin}
        │
        ▼  package_kb.py          build/packs/<lang>/  kb + embeddings + manifest
```

## Sources policy

**Public-domain or openly-licensed material only, always cited.**

- Each file in `knowledge/sources/` carries top-level `source` and
  `license` keys naming where the facts came from and under what terms.
- **Facts are fine** (emergency helpline numbers, scheme eligibility
  amounts published by the government for public use). **Text is not
  copied**: entries are written in Vaani's own words, in the target
  language, and reviewed by the language steward.
- Wikipedia-derived content must come from CC-BY-SA dumps with the
  article cited in the entry's `tags`-adjacent metadata when we add it.
- Anything whose license we cannot verify does not ship. No exceptions —
  a missing entry is recoverable, a license violation is not.

### Document schema (every source file)

A source file is a JSON object with metadata plus a `documents` list (a
bare JSON list is also accepted):

```json
{
  "source": "Government of India public emergency helpline numbers",
  "license": "Public domain (factual helpline numbers)",
  "documents": [
    {
      "id": "emergency-112-ta",
      "title": "தேசிய அவசர உதவி எண் 112",
      "lang": "ta",
      "text": "112 இந்தியாவின் தேசிய அவசர உதவி எண். ...",
      "tags": ["emergency", "national"]
    }
  ]
}
```

- `id` — globally unique, stable forever (packs and embeddings are keyed
  on it). Convention: `topic-lang`.
- `lang` — a BCP-47-ish code from `app/lib/core/constants.dart`
  (`ta`, `hi`, `bn`, `kn`, `te`, `mr`, `bho`, `mai`, `en`).
- Health-related entries **must** carry the "consult a doctor" disclaimer
  pattern; Vaani never gives medical advice.

## How stewards add sources

1. **Write** a new `knowledge/sources/<topic>.json` (copy the schema
   above) or extend an existing file — in your language, in your own
   words, with `source`/`license` filled in.
2. **Validate** without any setup:
   ```bash
   python knowledge/build_kb.py            # fails loudly on schema/license gaps
   ```
   `build_kb.py` hard-fails on missing fields, duplicate ids, or bad
   `tags`, and prints each problem with its file and index.
3. **Build + package** your language:
   ```bash
   python knowledge/build_embeddings.py
   python knowledge/package_kb.py --langs ta
   ```
4. **Open a PR**. Review by the language steward is required before a
   pack ships (see "Stewardship" in `docs/language-pack-spec.md`).

## The embedding contract: `nv-hash-v1`

The app computes embeddings **on-device, in pure Dart**
(`app/lib/data/services/knowledge/hybrid_search.dart`), and this pipeline
computes the **identical vectors in Python** so shipped packs and the app
agree bit-for-bit. The full algorithm — unicode-script-aware tokenizer
(word-character code-point ranges, danda exceptions, ASCII-only
lowercasing), signed FNV-1a hashing trick, 384 dimensions, L2 norm — is
specified in the docstring of `build_embeddings.py` and mirrored in the
Dart file. **If you change either side, change both in the same commit
and bump the contract name to `nv-hash-v2`.** The Dart test
`app/test/hybrid_search_test.dart` pins a vector generated by the Python
side to catch accidental drift.

These are placeholder embeddings (bag-of-words hashed): they match exact
tokens only. Real MiniLM embeddings arrive in Phase 6; the contract name
will change then, and packs will ship vectors instead of recomputing.

## Artifacts

| File | Written by | Purpose |
|---|---|---|
| `build/kb.json` | `build_kb.py` | Interchange format — always written, always the fallback |
| `build/kb.sqlite` | `build_kb.py` | FTS5 full-text index (`unicode61` tokenizer) for on-device/CLI queries; written only when the local Python's `sqlite3` has FTS5 (CPython on Linux/macOS/Windows does). When it is absent, `kb.json` **is** the documented fallback — nothing downstream breaks |
| `build/embeddings.json` | `build_embeddings.py` | Human-readable nv-hash-v1 vectors (rounded to 6 decimals) |
| `build/embeddings.bin` | `build_embeddings.py` | Binary twin: `b"NVEM"` magic, version byte `0x01`, `uint32-LE dim`, `uint32-LE count`, then per document `uint32-LE id-length`, id UTF-8 bytes, `dim × float32-LE` |
| `build/packs/<lang>/manifest.json` | `package_kb.py` | `format`, `language`, `version`, `embedding_algorithm`, `embedding_dim`, `document_count`, and every pack file's byte size + `sha256` — what the app verifies after a pack download. The GPG transport signature is added later by `scripts/release_language_pack.sh` |

`build/` is generated output — do not commit it.

## The app-side sample

`app/assets/knowledge/sample_kb.json` is a small, curated subset of this
pipeline's output format (18 entries across `ta`/`hi`/`en`) that ships in
the APK so the knowledge features work before any language pack is
installed. Keep it in this schema; regenerate topics from `sources/` when
in doubt.

## Commands (all stdlib-only, Python 3.8+)

```bash
python knowledge/build_kb.py                     # all languages
python knowledge/build_kb.py --language ta       # one language
python knowledge/build_embeddings.py
python knowledge/package_kb.py                   # every language → build/packs/
python knowledge/package_kb.py --langs ta,hi
```
